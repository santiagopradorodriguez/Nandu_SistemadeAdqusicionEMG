Nuevo Criterio de comparación y obtención del factor SNR


Para ejemplificar vamos a utilizar una de las mediciones realizadas. La de electrodos MediTrace chicos utilizados 1 vez la clase anterior.


Tomamos la medición realizando determinada cantidad de “esfuerzos” (activación del músculo) según un cronómetro. En este ejemplo un cronómetro de 50 ppm “esforzando” 15 veces el músculo que venimos midiendo estas clases (palmar corto). Esta técnica nos ayuda a recortar el audio que nos interesa analizar, “intuyendo” mejor donde está el potencial de activación en casos con mucho ruido. En el Reaper recortamos la señal para solo enfocarnos en la parte que nos interesa.


Le pasamos el audio a un programa que llamamos “analisis_por_track.py”. Este programa toma todos los archivos .wav de la carpeta que le pasemos para analizarlos y finalmente compararlos en una gran figura. Usando solo el archivo de audio que nos interesa, lo primero que se hace es tomar módulo y luego se “recorta” la señal en ventanas según el cronómetro. En cada ventana se busca el pico de amplitud máxima y se extrae un segmento alrededor de este. A continuación una imagen de este paso.
  

Luego, calculamos lo que denominamos “umbral de ruido”. Utilizamos diferentes métodos, quedándonos finalmente con el que mejor resultados da, según nuestra subjetividad (si lo que denominamos ruido queda debajo). Este es ‘rms_envelop’, se usa la envolvente del pulso promedio (calculada con la transformada de Hilbert) para localizar las zonas de baja energía (‘baseline’). En estas zonas se calculan los residuos entre cada pulso y el promedio; a partir de los residuos se estima la dispersión del ruido y se fija el umbral. Esta envolvente da una medida suave de la energía instantánea (parecida a la envolvente RMS, pero computada vía transformada analítica). ¿Para la envolvente podría usarse una envolvente por ventana móvil? (se trata de suavizar y obtener energía). En el código se comenta mejor línea por línea.


Luego, el código intenta estimar la RMS del ruido (noise_rms) de varias formas, en este orden:
* Muestras bajo el umbral del pulso promedio
Toma los tiempos del pulso promedio donde este es menor al umbral. Lo hace para todas las ventanas y calcula el RMS
* Fallback: outside_windows (si no hay suficientes muestras bajo umbral)
Si no hay suficientes muestras bajo el umbral, construye una máscara mask_outside que es True fuera de las ventanas alrededor de los máximos (maxima_per_cut ± pre_samples/post_samples). Si hay suficientes puntos fuera de ventanas, toma residuos_out = signal_recortada[idx_out] y noise_rms = rms(np.abs(residuos_out)).
* Fallback a sigma_est
Si los métodos anteriores fallan, usa sigma_est como noise_rms.
* Último recurso / ventanas antes del primer máximo
Si todo falla, toma una ventana pequeña antes del primer máximo y calcula RMS ahí.
* Si calcular_umbral fue False

Este documento describe cómo el sistema captura, guarda y posteriormente analiza los datos, enfocándose en la interacción entre el script de adquisición y el de análisis.
---
1. El Flujo de Guardado en `CodigoUnificador_integrado.py` (El Productor de Datos)
El script `CodigoUnificador_integrado.py` es el responsable de capturar las señales EMG y almacenarlas en el disco de una manera estructurada y autocontenida. El proceso se inicia cuando el usuario detiene una grabación.
Paso a Paso del Proceso de Guardado:


1.  Detener la Grabación: Cuando el usuario presiona "Detener Grabación", el método `on_record_click` se activa. Si había datos en memoria (`self.current_recording`), este método llama automáticamente a `on_export_click`.


2.  Solicitar Nombre: El método `on_export_click` muestra un cuadro de diálogo pidiendo al usuario un nombre para la medición (por ejemplo, `Electrodo_Seco_Biceps_Prueba1`). Este nombre es fundamental, ya que se usará como el nombre de la carpeta principal para todos los datos de esa sesión.


3.  Creación de la Estructura de Carpetas: El script crea una jerarquía de carpetas estandarizada dentro del directorio `base_de_datos_electrodos/`. La estructura es la siguiente:
    ```
    base_de_datos_electrodos/
    └── Electrodo_Seco_Biceps_Prueba1/  <-- Carpeta principal de la medición
        ├── canal_0/
        ├── canal_1/
        └── canal_2/
    ```
    Se crea una subcarpeta (`canal_0`, `canal_1`, etc.) para cada canal que fue grabado.
INSERTAR UNA IMAGEN SCREENSHOT DE LA INTERFAZ OSCILOSCOPIO
4.  Exportación en Múltiples Formatos: El script procede a guardar los datos en varios formatos, cada uno con un propósito específico:
    *   `metadata.json` (El Archivo Clave para el Análisis):
        *   Qué es: Antes de guardar la señal, el script recopila todos los parámetros de la sesión (la "metadata"). Esto incluye la frecuencia de muestreo, los BPM configurados, la duración de la fase de ruido y, muy importante, el conteo de pulsos (`pulse_count`) que lee del archivo `metronome_config.json` (si se usó el metrónomo).
        *   Dónde se guarda: Se guarda una copia idéntica de este archivo `metadata.json` dentro de cada subcarpeta de canal (`canal_0/metadata.json`, `canal_1/metadata.json`, etc.). Esto asegura que cada canal tenga toda la información contextual necesaria para su análisis individual.
    *   Archivos `.wav` (La Señal Primaria):
        *   Qué es: La señal de voltaje de cada canal se normaliza (su valor máximo se escala a 1.0) y se convierte a formato de audio de 16 bits.
        *   Dónde se guarda: Cada señal de canal se guarda como un archivo `.wav` individual dentro de su respectiva carpeta. Por ejemplo, `canal_0/grabacion.wav`. Este formato es ligero y universalmente compatible.
    *   Archivo `.csv` (Los Datos Crudos):
        *   Qué es: Se genera un único archivo de texto con valores separados por comas. Contiene una columna de tiempo y una columna con el voltaje crudo (sin normalizar) para cada canal.
        *   Dónde se guarda: Se guarda en la carpeta principal de la medición (ej. `Electrodo_Seco_Biceps_Prueba1/grabacion.csv`). Es útil para análisis en otros programas como Excel o MATLAB.
    *   Archivo `.png` (Visualización Rápida):
        *   Qué es: Se genera una imagen con el gráfico de la grabación completa para todos los canales.
        *   Dónde se guarda: También se guarda en la carpeta principal de la medición.
---
2. El Flujo de Carga en `analisis_por_track_integrado.py` (El Consumidor de Datos)
El script `analisis_por_track_integrado.py` está diseñado para "entender" la estructura de carpetas creada por el adquisidor. Su función es cargar los datos y los metadatos para realizar un análisis cuantitativo.
Paso a Paso del Proceso de Carga y Análisis:


1.  Selección de Medición y Canal: El usuario inicia el script, selecciona una o más carpetas de mediciones (ej. `Electrodo_Seco_Biceps_Prueba1`) y luego elige qué canales de esas mediciones quiere procesar.


2.  Localización de los Archivos Clave: Para cada canal seleccionado (ej. `canal_0` de la medición `Electrodo_Seco_Biceps_Prueba1`), el script sabe exactamente dónde buscar los archivos que necesita:
    *   Busca la señal en: `base_de_datos_electrodos/Electrodo_Seco_Biceps_Prueba1/canal_0/grabacion.wav`.
    *   Busca el contexto en: `base_de_datos_electrodos/Electrodo_Seco_Biceps_Prueba1/canal_0/metadata.json`.


3.  Carga y Reconstrucción de la Información:
    *   Carga de Metadatos: El script primero abre el `metadata.json`. De aquí extrae los parámetros cruciales que el adquisidor guardó:
        *   `bpm`: Para saber el período esperado entre pulsos.
        *   `noise_seconds`: Para saber qué parte inicial de la señal corresponde a ruido.
        *   `pulse_count`: El número exacto de pulsos que debe buscar, lo que hace la detección mucho más robusta.
    *   Carga de la Señal `.wav`: A continuación, carga el archivo `grabacion.wav`.
    *   Calibración (Paso Esencial): El archivo `.wav` contiene datos normalizados (de -1 a 1). Para recuperar la escala de voltaje original, el script busca el archivo `.csv` en la carpeta padre (`Electrodo_Seco_Biceps_Prueba1/grabacion.csv`), lee la columna de voltaje correspondiente al canal que está analizando, y encuentra su valor máximo absoluto. Este valor se usa como factor de calibración para reescalar la señal del `.wav` a sus unidades originales de Voltios.


4.  Ejecución del Análisis: Con la señal calibrada y todos los parámetros del `metadata.json`, el script `procesar_wavs_promedio` tiene todo lo necesario para:
    *   Identificar la ventana de ruido.
    *   Dividir la señal en segmentos según el `bpm` y el `pulse_count`.
    *   Detectar los picos dentro de cada segmento.
    *   Calcular el pulso promedio, la SNR y otras métricas.
    *   Guardar los resultados del análisis (`avg.png`, `pulses.png`, `results.json`) de nuevo en la misma carpeta del canal.
---
Diagrama del Flujo de Datos (Descripción textual)


Productor (CodigoUnificador_integrado.py):
1. Captura de Señal EMG
2. Grabación en Memoria
3. Al detener, se crea la estructura de carpetas: /Medicion/canal_i/
4. Se guardan los archivos:
   - metadata.json (en cada carpeta de canal)
   - grabacion.wav (en cada carpeta de canal)
   - grabacion.csv (en la carpeta de medición principal)


Consumidor (analisis_por_track_integrado.py):
1. El usuario selecciona la Medición y el Canal.
2. El script carga los archivos correspondientes:
   - Lee metadata.json para obtener los parámetros.
   - Lee grabacion.wav para obtener la señal normalizada.
   - Lee grabacion.csv para obtener el factor de calibración.
3. Se realiza el análisis de la señal combinando toda la información.
4. Se guardan los nuevos archivos de resultados (avg.png, results.json) en la misma carpeta del canal.

Discusión sobre filtro notch o rechaza banda


Entonces surge una pregunta que nos perturba. ¿Cómo tenemos que aplicar el filtro notch para preservar la señal?  Buscamos información al respecto , ya que por Fourier sabemos que al aplicar un filtro de esta característica estamos alterando drásticamente la fase de la señal cerca de la frecuencia de 50 hz. 


https://es.wikipedia.org/wiki/Fen%C3%B3meno_de_Gibbs


Buscamos distintos artículos donde se menciona esto.


El artículo "Reducing power line noise in EEG and MEG data via spectrum interpolation" (Reducción del ruido de la línea de alimentación en datos de EEG y MEG mediante interpolación del espectro), publicado en la revista NeuroImage en 2019 por Sabine Leske y Sarang S. Dalal, aborda el problema crítico de la interferencia de la red eléctrica (50 o 60 Hz) en los registros electrofisiológico PONER LINK AL ARTÍCULO


One of the possible causes for ringing artifacts is the Gibbs effect (Smith, 1997),
which can be especially pronounced when there are sharp discontinuities in the
filter’s frequency response (Fay and Kloppers, 2001). This is especially the case with
notch filters, due to the sharp and narrow stopband. Spectrum interpolation results in
a smoother Fourier spectrum, which has been shown to reduce the Gibbs
phenomenon (Brezinski et al., 2004).
Such signal distortions can be evaluated by examining the time and frequency
domain responses of the filter to artificial signals like an impulse or step signal. An
ideal frequency domain response would have unity passband and zero stop
magnitude. A real-world filter necessarily deviates from this ideal, with potential
ripples in the passband and stopband as well as a certain transition bandwidth. The
impulse and step responses reveal filter behavior in the time domain, visualizing the
amplitude and extent of distortions.
There are several studies reporting severe signal distortions in the temporal domain,
such as filter or ringing artifacts and artificial components after the application of
filters (Luck, 2005; Widmann et al., 2014). This might cause unwanted effects in the
MEG/EEG parameters of interest, e.g., a distortion of the peak amplitude (Acunzo et
al., 2012) or even artificial oscillations with a frequency near the cutoff frequency of
the filter (Widmann et al., 2014).


En el libro , Electromyography: Physiology, Engineering, and Noninvasive Applications 
menciona que para ciertos casos no es una buena práctica usar el filtro notch. PONERLINK AL LIBRO Y LA REFERENCIA DE LA PÁGINA


“These high-pass and low-pass filters are used to reduce noise and artifacts. In some cases analog notch filters have been used to reduce the 50 or 60Hz interference. In general, this is not a good practice because (1) it removes power from a frequency band where EMG shows high-power density and (2) introduces phase rotation that extends to frequencies below and above the central frequency thereby dramatically changing the wave-form (not so much the power) of the EMG. This latter issue is relevant when waveforms are of interest, but it is not important if only EMG amplitude or power is of interest, such as in EMG biofeedback. Digital adaptive noise cancellation filters may be used to remove power line interference and artifacts either on-line or off-line after signal sampling and A/D conversion. They lock on a predetermined waveform, estimate its amplitude and phase, and remove it by subtraction [45]”.

Resumen del método


_ Cambiamos la ventana de la envolvente a una grande, la de 250 ms. Esto hace que sea más lento, pero nos saca frecuencias o picos.
_ En cada medición, para cada canal se le restó a un recorte el ruido interpulso que le sigue (a la derecha). El ruido interpulso es el valor medio, entre 2 picos de señal, tomando un segmento de ¼ del período. Esto le saca el “piso” a todos los pulsos.
_ Luego se normaliza cada medición localmente, es decir, se normaliza cada recorte según la señal de la ventana más grande. Osea, en cada recorte de la medición se comparan los 3 canales y se normaliza por la señal mas grande. Esto deberia ser mejor, debido que si se utiliza solo un valor por medición, de repente pueden haber pulsos de mayor amplitud.
_ Esto puede ser opcional: Luego se filtra según el SNR interpulso ventana por ventana. Las ventanas que tengan SNR interpulso menor a 1 (este valor puede cambiar) son retiradas de la medición. Es decir, si yo tengo una medición con 20 pulsos, si 2 ventanas me dan con SNR interpulso menor a 1, se las saca y la medición queda con 18 pulsos.
_ Luego se hace un ciclo for para hacer un barrido de umbrales para los 3 canales. Tomamos como “umbrales validos” los que arrojen que las letras no repiten valores en el espacio.

Método de umbrales (Lucas)


Acá la idea fue utilizar el trabajo de Trevisan 2013, para discretizar las vocales y ubicarlas en un espacio tridimensional.


Este es el diagrama del procesamiento:
  

  

Primero se aislan los pulsos musculares “útiles” y se acondicionan las amplitudes. Se utilizan los datos del JSON de recortes. Se toma el 15% inicial y el 15% final de cada ventana para calcular la media del ruido  y la desviación estándar del ruido . A todo el pulso se le sustrae  para llevar la lı́nea base a cero.
Luego, se divide el pulso completo por el valor absoluto máximo global () encontrado en ese canal para llevar la amplitud a una escala de [0, 1].
La Relación Señal a Ruido de amplitud se calcula como . Dependiendo de la configuración seleccionada (Filtro Global, por Ventana, o Ambos), si el SNR no supera el umbral lı́mite exigido (e.g. 4.0), el pulso o la medición entera son descartados para no introducir falsos positivos.
Una vez normalizado el pulso, se requiere transformarlo a lógica digital (1 o 0) respecto
a un conjunto de umbrales. Puede buscarse un umbral único o por cada canal. De esta manera, cada ventana en el tiempo queda definida por una tupla o vector binario (por ejemplo, [1, 0, 1]). Se realiza una optimización basada en fuerza bruta sobre un espacio discreto. Se iteran todas las posibles combinaciones de umbrales desde 0,1 hasta 0,9 en pasos de 0,05.


Para cada combinación de umbrales testeada en el espacio de búsqueda, se analiza el
conjunto de vectores binarios resultantes para cada vocal:
_ Hay una moda global: Se calcula cuál es el vector binario más frecuente (Moda) para una vocal especı́fica.
_ Frecuencia Modal (Score): Es el porcentaje de veces que aparece la Moda Global sobre el total de pulsos válidos. El ”Score” del umbral testeado es el promedio de estas frecuencias modales.
_ Colisiones: Se verifica si dos vocales diferentes terminan teniendo el mismo vector binario como Moda Global. Esto se denomina “colisión” e invalida la capacidad discriminatoria del sistema.


El algoritmo busca minimizar estrictamente el número de colisiones, y en caso de empate, maximiza el Score (frecuencia de acierto promedio).

Pasamos a UMAP. Estuvimos haciendo pruebas rápidas. Luego se hizo el experimento para ver los parametros optimos y obtener la mejor configuración. Es un algoritmo “pre-programado” y conocido. Nosotros solo nos concentramos en como pasarle las mediciones (como lo hicimos en PCA) y como configuramos los hiperparámetros relevantes:
_ Vecinos (n_neighbors): Determina la cantidad de puntos cercanos que UMAP considera al construir el grafo difuso (radio de conectividad local).
• Valores bajos (5 - 15): UMAP se concentra de forma “miope” en la estructura local. Puede fragmentar clústeres grandes.
• Valores altos (30 - 50+): Empuja a UMAP a mirar la imagen global, forzando a que pulsos de la misma clase topológica se comporten como una sola masa.


_ Distancia Mı́nima (min_dist): Controla la cercanı́a mı́nima permitida entre puntos en la proyección final (2D/3D). Actúa como una “fuerza de repulsión” en el espacio reducido.
• Valores cercanos a 0.0: Los puntos colapsan unos sobre otros si son topológicamente (?) idénticos.
• Valores altos (ej. 0.5): Permite que los puntos “respiren”, esparciendo el clúster. Es útil si se busca interpretar la varianza natural y la distribución interna de una misma vocal en lugar de solo separarla.
